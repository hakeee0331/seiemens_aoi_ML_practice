01 · Executive summary

먼저 읽어야 할 결론

분석자마다 깊이는 달랐지만, 모델링의 핵심 위험에 대한 방향은 명확히 수렴한다.

이 데이터는 모델링할 수 있다. 단, “그냥 이진분류”로 다루면 안 된다.

07 · Quality review

그대로 채택하면 위험한 해석

좋은 아이디어와 검증이 필요한 주장을 분리한다.

0

모든 0을 “해당 없음”으로 바꾸면 안 된다

Dongjin 노트북은 0을 전역 sentinel로 보고 NaN으로 치환하지만, LSW와 Kimjaehak의 mapping 교차검증은 무효 셀이 비0일 수 있고 유효 측정값도 0일 수 있음을 보여준다. 유효성의 유일한 기준은 mapping.json이어야 한다.

!

“안전하게 제거” 목록은 split 전 확정하지 않는다

상수·준상수·고상관 피처는 전체 기간이 아니라 Train에서만 판정해야 한다. 특히 Dongjin의 type별 제거 수 22/36/40/39/43은 70개 실제 inspection feature 대신 출력에 “/99”를 쓰고 zero-based 유효성 가정을 포함하므로 최종 drop list로 사용하지 않는다.

L

라벨 충돌은 오류 신호이지 작업자 과실의 수학적 증명은 아니다

같은 익명 입력 signature에 다른 라벨이 존재하는 사실은 강하다. 그러나 누락된 변수, 반복 공정, 측정 정밀도, 실제 작업자 판정 오류를 현재 데이터만으로 분리할 수 없다. 삭제·다수결보다 audit flag와 강건성 실험이 우선이다.

ID

timestamp는 편리한 그룹 키이지만 PCB 고유 ID는 아니다

39,742개 timestamp 중 27,322개가 여러 inspection type을 포함해 보드 단위의 근사 그룹으로 유용하다. 다만 논문·데이터에 고유 PCB 식별자가 없으므로 실제 개체 동일성을 보장하지 않는다.

09 · Open questions

아직 답이 없는 질문

다음 EDA 또는 현업 확인 없이는 확정할 수 없는 항목이다.

익명 meta_feat1–4는 예측 시점에 실제로 사용 가능한가?
특정 값에서 불량률이 크게 높아 유용할 수 있지만, 사후 생성 정보나 배치 ID의 대리 변수라면 누수다. 원 컬럼 의미와 생성 시점을 확인해야 한다.
완전 중복 8,752건은 중복 로깅인가, 실제 반복 측정인가?
원인 확인 전 삭제하지 않는다. Train에서 세 가지 처리 전략을 비교하고 Validation/Test는 현실 빈도를 유지한다.
충돌 signature 70개는 실제 라벨 오류인가?
현재 데이터만으로 확정할 수 없다. 관련 14,037행을 audit flag로 관리하고, 제거·재가중·그대로 유지한 모델의 안정성을 비교한다.
후기 drift의 원인은 무엇인가?
검사유형 구성 변화만으로는 설명되지 않는다. 주별 PSI, 시간 판별 모델, rolling 성능으로 시점을 좁히고 AOI 설정 변경 여부를 확인한다.
