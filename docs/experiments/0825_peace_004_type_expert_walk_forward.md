# 0825_peace_004_type_expert_walk_forward

## 연결된 노트북

`notebooks/0825_peace_004_type_expert_walk_forward.ipynb`

## 상태

완료

## 목적

`0825_peace_003_type_expert_xgboost` Baseline의 모델·피처·파라미터·가중치 설정을 유지하고, 3-Fold expanding Walk-forward만 추가해 Validation에서 선택한 임계값의 미래 안정성을 검증한다.

## 주요 변경사항

- `mapping.json` 기반 타입별 유효 피처와 XGBoost 전문가 모델 5개 구성을 Baseline과 동일하게 유지했다.
- 클래스 가중치, 시간 가중치와 리샘플링은 적용하지 않았다.
- 첫 70% 개발 구간에서 Train, Calibration, Evaluation을 시간순으로 구성했다.
- 각 Fold의 Calibration에서 Recall 99% 이상을 만족하면서 False Call Reduction이 최대인 공통·타입별 임계값을 선택했다.
- 선택된 임계값을 바로 다음 미래 Evaluation에 변경 없이 적용했다.
- Walk-forward 이후 0~70% Train, 70~80% Validation, 80~100% Test 최종 평가를 Baseline과 동일하게 수행했다.
- 실행 로그는 `docs/peace/0825_peace_004_type_expert_walk_forward.log`에 저장했다.

## Walk-forward 구성

| Fold | Train | Calibration | Evaluation |
|---|---:|---:|---:|
| Fold 1 | 0~30% | 30~40% | 40~50% |
| Fold 2 | 0~40% | 40~50% | 50~60% |
| Fold 3 | 0~50% | 50~60% | 60~70% |

## 결론 및 다음 단계

- 공통 임계값은 미래 평가 평균 Recall 96.9%로 타입별 임계값의 92.4%보다 높고 변동도 작았다.
- 타입별 임계값은 평균 False Call Reduction이 33.4%로 공통 임계값의 16.9%보다 높지만, 최저 Recall이 78.9%까지 하락했다.
- 두 전략 모두 모든 미래 Fold에서 Recall 99%를 유지하지 못해 단일 Validation 결과만으로 운영 안정성을 판단할 수 없다.
- 임계값이 Fold별로 크게 달라져 시간에 따른 score 분포와 클래스 분포 변화가 확인됐다.
- 다음 실험은 이 Walk-forward 구조를 공통 검증 기준으로 고정하고 타입별 `scale_pos_weight`만 추가한다.
