## 목적

`0825_peace_004_type_expert_walk_forward`의 시간 분할, 타입별 유효 피처, XGBoost 파라미터, 임계값 선택 규칙은 그대로 유지하고, 각 타입의 현재 Train 데이터에서만 계산한 `scale_pos_weight = 음성 수 / 양성 수`를 Fold별·최종 학습에 적용했을 때 미래 안정성과 최종 Test 성능이 어떻게 바뀌는지 확인한다.

## 주요 변경사항

- `mapping.json` 기반 타입별 유효 피처와 XGBoost 전문가 모델 5개 구성은 유지했다.
- 시간 가중치, 리샘플링, Fold 앙상블은 적용하지 않았다.
- 각 Fold와 최종 0~70% 학습에서 타입별 Train 데이터만 사용해 `scale_pos_weight`를 다시 계산했다.
- Calibration Recall 99% 이상을 만족하는 공통·타입별 임계값 선택 규칙은 `0825_peace_004_type_expert_walk_forward`와 동일하게 유지했다.
- Walk-forward 이후 0~70% Train, 70~80% Validation, 80~100% Test 최종 평가도 동일하게 수행했다.
- 실행 로그는 `docs/peace/0825_peace_007_type_expert_class_weight.log`에 저장했다.

## 결론 및 다음 단계

- 클래스 가중치를 넣자 고정 0.5 기준의 미래 평균 Recall이 8.4%에서 59.6%로, 최종 Test Recall이 21.6%에서 65.8%로 크게 올라 score 자체의 민감도는 분명히 개선됐다.
- 공통 임계값 전략은 미래 평균 Recall이 96.9%에서 98.4%로 소폭 좋아졌지만, 최저 Recall은 95.4%라 여전히 99%를 안정적으로 지키지 못했다.
- 타입별 임계값 전략은 평균 False Call Reduction이 33.4%에서 39.1%로 올랐지만, 미래 Recall 99% 달성 Fold가 1개에서 0개로 줄어 안정성은 더 나빠졌다.
- 최종 Test에서는 Recall 99% 제약으로 선택된 threshold가 지나치게 낮아져 공통 임계값 FCR이 60.9%에서 10.1%로, 타입별 임계값 FCR이 46.7%에서 32.1%로 크게 악화됐다.
- 따라서 `scale_pos_weight` 단독 적용은 기본 0.5 판정에는 도움이 되지만, 현재의 Recall 99% threshold 선택 규칙과 결합하면 운영 오탐 비용이 너무 커진다.
- 다음 실험은 같은 Walk-forward 틀에서 시간 가중치를 분리 평가하고, 클래스 가중치를 계속 사용할지 여부는 threshold 선택 규칙 재설계까지 포함해 다시 판단한다.
