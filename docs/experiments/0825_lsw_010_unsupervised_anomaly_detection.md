# 0825_lsw_010_unsupervised_anomaly_detection

## 연결된 노트북

`notebooks/0825_lsw_010_unsupervised_anomaly_detection.ipynb`

## 상태

완료

## 목적

로드맵 Phase 4(비지도 이상탐지). dongjin의 `0824_dongjin_015_isolation_forest`가 이미 단독
사용은 약하다는 걸 보였다(Test PR-AUC 0.036). 이번 노트북은:

1. **단독 평가**: False call(class=0) Train만으로 검사유형별 Isolation Forest를 학습, 우리
   표준 파이프라인(Slip Rate ≤1% 제약 threshold, Volume Reduction, 총비용)으로 평가.
2. **결합**: 이상 점수를 XGBoost의 추가 입력 피처로 넣어, 004/007/009까지 확정된 "현재 최고
   조합" 위에서 개선되는지 확인(로드맵 4-3).

## 방법론 노트 (실수 기록)

1차 실행에서 type2만 개선되는 것처럼 보였으나, type2의 튜닝 하이퍼파라미터를 옮겨적으며
**009 Phase B(리샘플링 데이터 기준 진짜 승자, candidate 1)가 아니라 Phase A(baseline 데이터
기준 승자, candidate 15)를 잘못 복사**한 버그였다. `champion_results`를 009 원본과 직접
재현·대조해서 잡았다.

## 주요 결과

### 단독 평가 (dongjin 결론 재확인)

Isolation Forest 단독은 PR-AUC 0.01~0.11로 XGBoost(0.02~0.40)보다 훨씬 약함 — dongjin의
결론이 재현된다. 다만 총비용 기준으로는 생각보다 덜 나쁘다: type1(7,874 vs XGB 8,539)은
오히려 더 싸고, type0·type4는 거의 동률, type2(18,111 vs 15,078)만 뚜렷하게 나쁨. PR-AUC가
훨씬 낮아도 Slip-Rate 제약 threshold가 그 차이를 어느 정도 흡수한다는 "PR-AUC ≠ 운영지표"
패턴의 또 다른 사례.

### 결합 — 이상점수를 XGBoost 피처로 추가 (버그 수정 후 정답)

| type | 챔피언 총비용(1:10→1:100) | +이상점수 | 개선 |
|---|---|---|---:|
| 0 | 5,678 → 9,818 | 7,186 → 10,246 | +1,508 / +428 (악화) |
| 1 | 5,873 → 7,289 | 5,986 → 7,897 | +113 / +608 (악화) |
| 2 | 6,316 → 13,516 | 6,932 → 14,402 | +616 / +886 (악화) |
| 3 | 10,103 → 16,313 | 20,257 → 23,407 | +10,154 / +7,094 (크게 악화) |
| 4 | 715 → 715 | 727 → 727 | +12 / +12 (표본 부족) |

전 유형·전 시나리오에서 예외 없이 악화됐다. type3(SMOTE 데이터)에서 가장 크게 나빠졌는데,
SMOTE가 만든 합성 행에 원본 정상 분포로 학습한 Isolation Forest 점수를 매기는 게 의미가
약했을 가능성이 크다.

## 결론

- 비지도 이상탐지 단독은 dongjin 결과대로 약함 — 재확인.
- 이상 점수를 지도학습 피처로 얹는 결합 방식도 통하지 않음 — 004/007/009의 "현재 최고"를 어느
  유형에서도 못 이김. Phase 4는 "단순 분류기 이상의 시도를 했다"는 스토리는 만들 수 있지만
  성능 개선으로는 이어지지 않았다는 게 정직한 결론.
- 안 해본 결합 방식: (a) 이상 점수-XGBoost 확률 앙상블, (b) 이상 점수가 높은데 XGBoost는
  정상이라 판단한 애매한 케이스만 추가 수동검사로 보내는 규칙 기반 결합.
