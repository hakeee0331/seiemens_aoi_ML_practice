# Siemens PCB AOI 데이터 설명

이 문서는 `docs/data_example.md` 형식을 참고하여 실제 원본 데이터의 구조와 취급 규칙을 기록한다. 실제 데이터 행이나 불필요한 고유값은 포함하지 않는다.

## 출처와 분석 범위

- 데이터 설명 논문: *Data of automated optical inspection of surface-mounted technology electronic production*, Pfab et al., Data in Brief 53 (2024) 110110
- DOI: `10.1016/j.dib.2024.110110`
- 로컬 논문: `docs/1-s2.0-S2352340924000830-main.pdf`
- 원본 데이터: `data/raw/dataset.csv`
- 검사 피처 매핑: `data/raw/mapping.json`
- 재현 노트북: `notebooks/0823_kimjaehak_001_eda.ipynb`

논문에 따르면 데이터는 Siemens AG 독일 생산라인 한 곳에서 132일 동안 수집되었다. AOI가 정상으로 판정한 지점은 포함하지 않고, AOI가 불량으로 의심해 수동 검사로 보낸 납땜 지점만 포함한다.

## 파일 구조

| 파일 | 형식 | 구조 | 역할 |
|---|---|---|---|
| `dataset.csv` | CSV | 440,274행 × 공식 컬럼 77개, 별도 행 식별자 1개 | 익명화된 AOI 측정값과 수동 검사 라벨 |
| `mapping.json` | JSON | 검사유형 `0`~`4`의 피처 목록 | 검사유형별 유효 `inspection_feat` 정의 |

`dataset.csv`의 첫 열은 헤더가 없는 고유 행 식별자다. EDA에서는 이를 `record_id`로 이름 붙였으며 모델 입력으로 사용하지 않는다.

## 컬럼 스키마

| 컬럼 | 데이터 타입 | 역할 | 결측값 | 설명 |
|---|---|---|---:|---|
| 첫 번째 헤더 없는 열 | 정수 | 식별자 | 0 | 행 번호이며 공식 77개 컬럼에는 포함되지 않음 |
| `timestamp` | 문자열/UTC datetime 변환 가능 | 시간 및 그룹 | 0 | PCB가 AOI에 진입한 시각. 연도는 1970으로 익명화됨 |
| `class` | 정수 범주형 | 타깃 | 0 | `0`=false call(실제 정상), `1`=true defect(실제 불량) |
| `inspection_type` | 정수 범주형 | 입력/분기 기준 | 0 | 검사 구성 유형 `0`~`4` |
| `meta_feat1`~`meta_feat4` | 정수 범주형 | 입력 | 0 | 익명화된 에러 코드, 부품 종류, 실장 각도 등의 메타정보 |
| `inspection_feat*` 70개 | 실수 | 입력 | 0 | AOI 이미지에서 산출되어 [0, 1]로 익명화된 측정값 |

공식 77개 컬럼의 자료형은 실수 70개, 정수 6개, 문자열 1개다. `meta_feat`의 고유 범주 수는 각각 75, 5, 2, 49개다.

## 타깃과 검사유형 분포

| inspection_type | 전체 | false call (`class=0`) | true defect (`class=1`) | true defect 비율 |
|---:|---:|---:|---:|---:|
| 0 | 97,053 | 96,735 | 318 | 0.3277% |
| 1 | 57,673 | 56,095 | 1,578 | 2.7361% |
| 2 | 128,174 | 126,828 | 1,346 | 1.0501% |
| 3 | 151,931 | 150,650 | 1,281 | 0.8431% |
| 4 | 5,443 | 5,344 | 99 | 1.8188% |
| 전체 | 440,274 | 435,652 | 4,622 | 1.0498% |

클래스가 극도로 불균형하고 검사유형별 비율 차이도 크다. 단순 Accuracy만으로 모델을 평가하지 않는다.

## 검사유형별 피처 규칙

| inspection_type | 매핑된 유효 피처 | 유효 피처 중 상수열 | 매핑 제외 피처 | 매핑 제외 셀의 0 비율 |
|---:|---:|---:|---:|---:|
| 0 | 44 | 7 | 26 | 61.5385% |
| 1 | 52 | 28 | 18 | 44.4452% |
| 2 | 65 | 45 | 5 | 0% |
| 3 | 65 | 46 | 5 | 0% |
| 4 | 21 | 8 | 49 | 72.4713% |

- 모든 검사유형에 공통으로 유효한 검사 피처는 17개다.
- 70개 검사 피처 중 65개는 적어도 한 검사유형에 매핑되며 5개는 어떤 유형에도 매핑되지 않는다.
- 논문은 미사용 피처의 기본값을 0으로 설명하지만 실제 CSV에서는 매핑 제외 셀이 항상 0이 아니다.
- 값이 0인지 여부로 유효 피처를 추정하지 않고 반드시 `mapping.json`을 적용한다.
- 동일한 `inspection_feat` 컬럼도 검사유형에 따라 물리적 의미가 달라질 수 있으므로 전체 유형을 섞은 단일 변수 해석에 주의한다.

전체 기간을 기준으로 상수, 준상수(최빈값 비율 99% 이상), 저분산(분산 `1e-4` 이하)을 제외한 잠정 검사 피처 후보는 type 0~4에서 각각 27, 12, 18, 17, 10개다. 이 목록은 EDA 참고값이며 실제 선택기는 시간순 분할 후 학습 데이터에만 적합한다.

매핑 제외 피처의 비0 값도 type 0·1·4에서 유효값 집합과 상당 부분 정확히 겹친다. 따라서 0, 센티널 값 또는 값 범위를 이용한 마스킹은 사용하지 않는다.

## 데이터 품질

- NaN 결측 셀: 0건
- 수치형 무한값: 0건
- 검사 피처의 [0, 1] 범위 이탈: 0건
- 중복 행 식별자: 0건
- `record_id`를 제외한 완전 중복 초과 행: 8,752건(1.99%)
- 완전 중복 그룹에 포함된 전체 행: 13,002건
- 전체 데이터 기준 상수 검사 피처: 6개
- 시간·타깃 제외 입력 signature: 391,922개
- 반복 입력 signature: 10,458개 그룹, 58,810행
- label conflict가 있는 입력 signature: 70개 그룹, 14,037행

완전 중복이 중복 로깅인지 실제 반복 측정인지 확인되지 않았으므로 원인을 분석하기 전에 임의로 제거하지 않는다.

## 시간 및 그룹 구조

- 시각 범위: `1970-06-23 03:58:55+00:00`부터 `1970-11-02 14:21:28+00:00`
- 시간 범위: 132일
- 실제 관측일: 101일
- 범위 내 비관측일: 32일
- 고유 timestamp 그룹: 39,742개
- 두 행 이상인 timestamp 그룹: 33,902개
- 여러 검사유형을 포함하는 timestamp 그룹: 27,322개
- 서로 다른 라벨을 포함하는 timestamp 그룹: 715개

논문은 같은 PCB의 여러 납땜 지점이 동일 timestamp를 가질 수 있다고 설명한다. timestamp는 완전한 PCB 식별자가 아니라 그룹 대리 변수이므로 한계를 명시하되, 동일 timestamp 그룹이 Train과 Validation/Test에 동시에 포함되지 않도록 분할하는 것이 안전하다.

## 시간순 분할과 분포 변화

timestamp 그룹을 유지한 누적 행 수 기준 60/20/20 시간순 분할 결과는 다음과 같다.

| split | 행 | timestamp 그룹 | true defect 비율 | 기간 |
|---|---:|---:|---:|---|
| train | 264,343 | 26,063 | 0.7191% | 1970-06-23 ~ 1970-09-28 |
| validation | 87,879 | 6,586 | 0.4506% | 1970-09-28 ~ 1970-10-13 |
| test | 88,052 | 7,093 | 2.6405% | 1970-10-13 ~ 1970-11-02 |

- 분할 경계를 가로지르는 timestamp 그룹은 0개다.
- test의 true defect 비율은 train의 약 3.67배다.
- train 대비 test의 검사유형 구성비는 type 2가 -9.3671%p, type 3이 +6.3645%p 변했다.
- 검사유형별 유효·비상수 피처 113개에 대한 train-to-test PSI에서 67개는 0.10 미만, 26개는 0.10~0.25, 20개는 0.25 이상이었다.
- type 4는 13개 피처 중 11개가 PSI 0.25 이상이지만 test 표본이 728행으로 작아 표본 및 binning 민감성을 함께 고려한다.

## split 간 입력 signature 재등장

- 둘 이상의 split에 나타나는 입력 signature: 2,948개(고유 signature의 0.7522%)
- 관련 행: 30,455건
- validation에서 train에 이미 나타난 signature 행: 4,268건(4.8567%)
- test에서 train 또는 validation에 이미 나타난 signature 행: 8,515건(9.6704%)
- cross-split label conflict signature: 43개

signature는 pandas 64-bit 해시로 분석한 입력 벡터 그룹이며 PCB 식별자가 아니다. 모델 평가에서는 전체 성능과 함께 과거에 본 signature 및 처음 보는 signature의 성능을 분리해 보고한다.

## 모델링 전 주의사항

- 원본 파일을 수정하거나 덮어쓰지 않는다.
- 검사유형별 유효 피처는 `mapping.json`으로 선택한다.
- 검사유형별 상수열과 저분산열은 학습 데이터에서만 판단해 제거한다.
- 시간순 분할과 timestamp 그룹 경계를 함께 고려한다.
- 전처리 통계는 데이터 분할 후 학습 데이터에만 `fit`한다.
- 불균형을 반영해 PR-AUC, true-defect recall, false-call reduction 등 운영 목적에 맞는 지표를 사용한다.
- 작업자 단독 판정에 따른 라벨 노이즈와 알려지지 않은 distribution drift 가능성을 가정한다.
