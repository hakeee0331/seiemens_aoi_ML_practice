완료

## 목적

003~008은 전부 데이터(리샘플링/라벨정제/가중치)나 임계값 정책만 바꿨고, **XGBoost 모델 자체의
하이퍼파라미터는 한 번도 튜닝하지 않았다**(계속 기본값). 임계값이 극단으로 내려가는 현상, 표본
작은 유형의 불안정성 등이 정규화 부족 신호로 보여 가볍게(무작위 20개 조합) 탐색한다.

- Phase A: 리샘플링 없이 baseline 데이터로 하이퍼파라미터만 바꿔 baseline과 비교.
- Phase B: 각 유형의 현재 최고 기법(리샘플링/라벨정제) 데이터 위에서 하이퍼파라미터를 다시
  탐색해 "현재 최고" 대비 더 개선되는지 확인.

## 방법론 노트 (실수 2건)

- Phase A 코드에서 후보 리스트의 기본값 항목을 `dict.pop()`으로 제거하다가 공유 리스트 자체를
  변형시켜, Phase B에서 "기본값 후보"를 못 찾는 버그가 있었다 — `candidate_idx == 0`으로 기본값을
  판별하도록 수정.
- Phase B 1차 시도는 Phase A에서 baseline 데이터로 고른 챔피언 설정을 리샘플링된 데이터에 그대로
  재사용했다가 전 유형에서 참패했다(예: type0 TN=0, FN=0까지 붕괴). 리샘플링은 양성:음성 비율을
  크게 바꾸는데 baseline에 맞춘 정규화 강도가 그 비율에는 안 맞았기 때문 — 해당 데이터 위에서
  하이퍼파라미터를 다시 탐색하도록 수정했다.

크고 일관된 단일 개선.

### Phase B (현재 최고 기법 데이터 위에서 재탐색)

| type | 기법 | 현재최고(기본HP) | 튜닝HP | 개선 |
|---|---|---|---|---:|
| 0 | label_cleansing | 5,678 → 9,818 | 동일 | 0 / 0 |
| 1 | undersample | 6,209 → 7,289 | 5,873 → 9,113 | -336 / +1,824(악화) |
| 2 | undersample | 10,541 → 14,411 | 6,316 → 13,516 | -4,225 / -895 |
| 3 | smote(cleanlab 근사)* | 19,666 → 22,456 | 10,103 → 16,313 | -9,563 / -6,143 |
| 4 | undersample | 715 → 715 | 동일 | 0 / 0 |

\* type3의 "현재최고"는 007의 실제 cleanlab+smote가 아니라 smote만 적용한 근사치다(cleanlab
이슈 마스크를 이 노트북에서 재계산하지 않음) — 실제 cleanlab+smote 위에서 재탐색하면 숫자가
달라질 수 있어 다음 세션에서 재확인이 필요하다.

type1은 1:10에서는 튜닝이 이겼지만(-336) 1:100에서는 오히려 악화(+1,824)됐다 — Validation
기준으로 고른 설정이 Test에서 어긋난 일반화 실패 사례. 가벼운 랜덤서치도 특정 비용 시나리오에
과적합할 수 있다는 경고.
