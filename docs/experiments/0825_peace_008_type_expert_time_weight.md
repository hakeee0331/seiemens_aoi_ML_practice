## 목적

`0825_peace_004_type_expert_walk_forward`의 시간 분할, 피처, XGBoost 파라미터, 임계값 선택과 평가 절차를 그대로 유지한 채, 각 타입별 Train 내부 시간순 `sample_weight`만 1.0→2.0 선형 증가로 추가해 성능 변화를 확인한다.

## 주요 변경사항

- `mapping.json` 기반 타입별 유효 피처와 XGBoost 전문가 모델 5개 구성은 `004`와 동일하게 유지했다.
- 각 Fold와 최종 0~70% 학습에서 타입별 Train 구간의 earliest timestamp에 1.0, latest timestamp에 2.0이 되도록 `sample_weight`를 선형 증가시켰다.
- 같은 timestamp만 있는 퇴화 케이스를 처리하는 함수를 넣고, 각 학습마다 `time_weight_min`, `time_weight_max`, `time_weight_mean`, `time_weight_degenerate`를 로그와 표에 저장했다.
- 실행된 모든 학습 요약에서 `time_weight_degenerate=False`였고, 실제 가중치 범위는 모두 1.0~2.0으로 생성됐다.
- Walk-forward와 최종 Test는 `004`처럼 단일 타입별 모델만 사용했고, Fold 앙상블은 적용하지 않았다.
- 실행 로그는 `docs/peace/0825_peace_008_type_expert_time_weight.log`에 저장했다.

## 결론 및 다음 단계

- 시간 가중치를 넣은 뒤 최종 Test PR-AUC는 0.371587로 `004`의 0.318360보다 상승했다.
- 공통 임계값 전략은 Test Recall이 89.8%에서 90.8%로 소폭 개선됐지만, False Call Reduction은 60.9%에서 49.8%로 하락했다.
- 타입별 임계값 전략은 Test Recall이 92.7%에서 94.2%로 개선됐지만, False Call Reduction은 46.7%에서 31.3%로 더 크게 하락했다.
- Walk-forward 기준으로도 공통 임계값 평균 Recall 97.6%, 타입별 평균 Recall 93.7%로 `004`보다 소폭 좋아졌지만, 여전히 모든 미래 Fold에서 Recall 99%를 안정적으로 유지하지는 못했다.
- 시간 가중치는 score ranking과 Recall을 개선하는 방향으로 작동했지만, 운영 threshold에서는 FP가 급증해 비용 절감 지표를 희생했다.
- `007` 클래스 가중치와 비교하면 시간 가중치가 Test PR-AUC와 공통 임계값 FCR이 더 높아, Recall 99% 단일 목표가 아니라면 우선 후보로 본다.
