이번 프로젝트에서 선택한 방식

작게 시작하고, 필요해질 때만 구조를 확장합니다.

NB

노트북 중심 실험

탐색, 전처리, 학습, 평가를 우선 노트북 안에서 수행합니다. 공통 로직이 안정되기 전에는 src/를 만들지 않습니다.

↻

실행 시 전처리

data/processed/를 두지 않고 실행할 때마다 전처리합니다. 원본 데이터는 data/raw/에서 수정하지 않습니다.

◎

결과는 노트북에서

별도 results/ 폴더 없이 노트북 출력과 대응 실험 문서로 결과를 공유합니다. 모델 파일은 생성하되 Git에는 올리지 않습니다.

공용 작업 흐름

Issue 하나가 짧게 유지되는 작업 브랜치 하나와 연결됩니다.

Issue 생성 목적, 할 일, 완료 조건 작성
브랜치 생성 12-baseline-model
실험 및 기록 노트북 + 실험 문서 + index
PR 및 리뷰 Closes #12로 연결
main 병합 가능하면 squash, 브랜치 삭제

브랜치가 실제로 움직이는 모습

개인 실험 브랜치는 main에 직접 병합하지 않습니다.

공동 기준 main Issue 작업 브랜치 개인 sandbox main 변경 가져오기

개인 실험 브랜치 사용법

공유·백업이 필요하지 않다면 GitHub에 올리지 않아도 됩니다.

브랜치 이름

공용 작업
12-baseline-model
15-fix-data-split

개인 실험
sandbox/jaehak/xgboost
sandbox/minji/feature-selection

기억할 규칙

  • 개인 실험은 로컬 브랜치를 기본으로 사용합니다.
  • 백업, 기기 이동, 중간 공유가 필요할 때만 원격에 push합니다.
  • sandbox 브랜치는 main으로 직접 PR하거나 병합하지 않습니다.
  • 공용 반영이 필요하면 Issue를 만들고 최신 main에서 정식 작업 브랜치를 생성합니다.

저장소 구조

현재 필요한 것만 둔 최소 구성입니다.

siemens_aoi/
├── README.md
├── CONTRIBUTING.md
├── AGENTS.md
├── requirements.txt
├── .gitignore
├── .github/
│   ├── ISSUE_TEMPLATE/task.yml
│   └── pull_request_template.md
├── data/raw/
├── docs/
│   ├── project_status.html
│   ├── data_example.md
│   └── experiments/
├── notebooks/
└── models/

폴더 역할

  • data/raw/: 전달받은 익명 원본 데이터
  • notebooks/: 탐색, 전처리, 학습, 평가
  • docs/experiments/: 노트북과 1:1 대응하는 설명
  • models/: 노트북이 생성한 모델 파일
  • src/, results/, data/processed/: 현재는 사용하지 않음

팀원이 바로 기억할 것

세부 내용의 원본은 CONTRIBUTING.md입니다.

실험 파일

MMDD_작성자_실험번호_설명 형식을 사용하고, 노트북·실험 문서·모델의 stem을 동일하게 맞춥니다.

0823_jaehak_002_baseline.ipynb

커밋 메시지

<type>: <변경 내용> 형식을 사용하고 하나의 커밋에는 하나의 논리적 변경을 담습니다.

exp data feat fix docs chore refactor
이 페이지는 팀 공유용 협업 규칙 요약입니다. 규칙이 충돌할 경우 CONTRIBUTING.md를 기준으로 판단합니다.
