## 목적

`0825_peace_004_type_expert_walk_forward`의 시간 분할, 타입별 유효 피처, XGBoost 파라미터, 임계값 선택 규칙은 그대로 유지하고, 각 타입의 현재 Train 데이터에서만 계산한 `scale_pos_weight = sqrt(음성 수 / 양성 수)`와 시간순 `sample_weight 1.0→2.0`를 Fold별·최종 학습에 함께 적용했을 때 미래 안정성과 최종 Test 성능이 어떻게 바뀌는지 확인한다.

## 주요 변경사항

- `mapping.json` 기반 타입별 유효 피처와 XGBoost 전문가 모델 5개 구성은 유지했다.
- 각 Fold와 최종 0~70% 학습에서 타입별 Train 데이터만 사용해 raw class ratio `n_negative / n_positive`를 계산한 뒤 `sqrt`를 취해 `scale_pos_weight`로 적용했다.
- 같은 학습 구간 내부 시간순 위치를 사용해 `sample_weight`를 1.0에서 2.0까지 선형 증가시켰다.
- 모든 학습에서 `scale_pos_weight_raw`, `scale_pos_weight_sqrt`, `time_weight_min`, `time_weight_max`, `time_weight_mean`, `time_weight_degenerate`를 로그와 요약 표에 저장했다.
- Walk-forward와 최종 Test는 `004`처럼 단일 타입별 모델만 사용했고, Fold 앙상블은 적용하지 않았다.
- 실행 로그는 `docs/peace/0825_peace_010_type_expert_sqrt_class_time_weight.log`에 저장했다.

## 결론 및 다음 단계

- `sqrt(scale_pos_weight)`를 함께 넣자 `007`의 과도한 클래스 가중치보다 score 분포 왜곡이 줄어, 최종 Test PR-AUC가 0.318605에서 0.384672로 올라갔다.
- 고정 0.5 기준 Test Recall은 49.2%로 `007`의 65.8%보다 낮아졌지만, FCR은 93.7%에서 97.4%로 회복됐다. 즉 강한 클래스 가중치의 민감도 증가는 줄이고 precision 쪽 균형을 일부 되찾았다.
- 공통 임계값 전략은 Test Recall 96.0%, FCR 19.1%를 기록해 `007`의 98.5% / 10.1%보다는 덜 극단적이지만, `008` 시간 가중치 단독의 90.8% / 49.8%보다 FP 비용이 여전히 훨씬 크다.
- 타입별 임계값 전략은 Test Recall 94.3%, FCR 31.7%로 `008`의 94.2% / 31.3%와 거의 비슷하고, `007`의 93.9% / 32.1%보다는 약간 낫다.
- Walk-forward 기준으로도 공통 임계값 평균 Recall 98.7%, 타입별 평균 Recall 92.1%로 99% 미래 안정성은 여전히 확보하지 못했다.
- 따라서 클래스 가중치를 `sqrt`로 약화한 방향성 자체는 타당하지만, 현재 Recall 99% 제약 운영 목적에서는 시간 가중치 단독(`008`)이 더 실용적이며, 결합 설정은 threshold 규칙을 다시 설계할 때 재검토하는 편이 안전하다.
