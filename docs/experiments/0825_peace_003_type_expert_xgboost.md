# 0825_peace_003_type_expert_xgboost

## 연결된 노트북

`notebooks/0825_peace_003_type_expert_xgboost.ipynb`

## 상태

완료

## 목적

`mapping.json`에 정의된 검사유형별 유효 피처만 사용해 XGBoost 전문가 모델 5개를 학습하고, 이후 클래스 가중치와 시간 가중치 실험의 비교 기준을 만든다.

## 주요 변경사항

- 원본 440,274행을 수정하거나 중복 제거하지 않고 그대로 사용했다.
- timestamp 그룹 경계를 보존한 70% Train, 10% Validation, 20% Test 시간순 분할을 적용했다.
- 각 타입 모델은 공통 `meta_feat1`~`meta_feat4`와 해당 타입에 매핑된 `inspection_feat`만 입력받는다.
- `meta_feat`는 Train에서 fit한 One-hot encoder로 변환하고 검사 피처는 그대로 사용했다.
- 클래스 가중치, 시간 가중치와 리샘플링은 적용하지 않았다.
- Validation Recall 99% 이상을 만족하면서 False Call Reduction이 최대인 임계값을 자동 선택하는 함수를 추가했다.
- 공통 임계값 1개와 타입별 임계값 5개를 Validation에서 선택했다.
- Validation 확인 후 모델·피처·파라미터와 선택된 임계값을 변경하지 않고 Test를 한 번 평가했다.
- 실행 로그는 `docs/peace/0825_peace_003_type_expert_xgboost.log`에 저장했다.

## 평가 방법

- `class=1`을 Real Defect positive class로 사용했다.
- Validation과 Test에서 PR-AUC, ROC-AUC, Accuracy, Precision, Recall, F1, TP, FN, FP, TN, False Call Reduction을 계산했다.
- 타입별 확률을 원래 행 순서로 결합한 pooled 성능과 타입별 성능을 함께 확인했다.
- threshold 0.5, 공통 임계값, 타입별 임계값의 결과를 함께 비교했다.
- 임계값 선택에는 Validation만 사용하고 Test에서 임계값을 다시 계산하지 않았다.

## 결론 및 다음 단계

- Test PR-AUC는 0.318360이지만 threshold 0.5에서 실제 불량 2,325건 중 1,822건을 놓쳐 운영 Recall이 부족하다.
- Type 0과 Type 4는 Test 실제 불량을 한 건도 탐지하지 못해 타입별 클래스 불균형의 영향이 크다.
- Validation에서는 두 자동 임계값 전략이 Recall 99%를 충족했지만 Test에서는 공통 89.81%, 타입별 92.69%로 하락했다.
- 타입별 임계값은 공통 임계값보다 불량 67건을 더 탐지했지만 False Call Reduction이 60.94%에서 46.69%로 낮아졌다.
- 현재 베이스라인에서는 공통 임계값이 더 높은 수동검사 절감량을 보였고, 두 전략 모두 미래 Recall 안정성 목표에는 미달했다.
- 다음 실험은 같은 데이터 분할, 피처, XGBoost 파라미터와 평가 지표를 유지하고 타입별 `scale_pos_weight`만 추가한다.
- 이후 시간 가중치는 별도 실험으로 분리해 각 변경의 효과를 독립적으로 비교한다.
